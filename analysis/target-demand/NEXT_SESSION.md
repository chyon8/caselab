# 재착수 메모 — 현재 결론 사용 금지

작성: 2026-09-23

## 먼저 알아야 할 결론

이전의 **기존 서비스 보완 / 화면·프런트 한정 / 소개 홈페이지** 결론은 사용자가 요구한
마케팅 타깃 분석의 답이 아니었다. 잘못된 보고서·근거표·대시보드·전용 분류 코드는 Git에서
제거했다. 복원하거나 최종 추천으로 공유하지 않는다.

이번 실패는 데이터를 못 모은 문제가 아니라, 분석 질문을 잘못 정의한 문제다.

## 사용자가 실제로 원하는 질문

공고 원문에서 반복되는 **고객 업종 × 구체적인 업무·시스템·문제** 조합을 찾아야 한다.

사용자가 든 “물류 기업이 내부 시스템을 개발”은 형식의 예시일 뿐, 물류나 내부 시스템으로
분석 범위를 제한하라는 뜻이 아니다. 가능한 모든 수요 중 실제 공고에서 충분히 반복되고 성과
차이가 있는 조합을 찾아, 마케팅팀이 우선 검토할 타깃 후보를 판단할 수 있게 해야 한다.

예시 형식:

`발주사 또는 서비스 대상 업종` × `해결하려는 구체적 업무/운영 문제` × `만들려는 시스템·서비스`

업종이 원문에 명시되지 않으면 추정하지 않고 `미상`으로 남긴다. 발주사 업종과 서비스 대상
업종도 섞지 않는다.

## 내가 잘못한 점

1. 원문에서 **업종·사용 맥락·업무 문제·시스템**을 함께 추출하지 않고, 결과물/개발 방식 중심의
   넓은 수요 태그 28개로 축소했다.
2. 그래서 “기존 서비스 보완”, “화면 디자인”처럼 너무 넓고 마케팅 타깃으로 쓸 수 없는 결과를
   만들었다.
3. 사용자의 물류 예시를 ‘예시일 뿐’이라고 이해하면서도, 그 예시가 요구한 **조합 단위의 분석**을
   결과 정의에 반영하지 못했다.
4. 이 목표 적합성 검토 전에 분석 완료·대시보드까지 만들었다. 잘못된 결론을 시각화한 화면도
   제거했으며, 새 결과가 나오기 전에는 대시보드를 만들지 않는다.

## 재착수 때의 분석 단위와 산출물

각 후보는 다음을 모두 갖춘 구체적 조합이어야 한다.

| 항목 | 필수 내용 |
|---|---|
| 타깃 정의 | 업종(발주사/서비스 대상 구분), 업무·문제, 시스템/서비스를 한 문장으로 정의 |
| 포함·제외 기준 | 어떤 원문 표현을 넣고 빼는지 |
| 원문 근거 | 식별정보 없는 실제 공고 사례와 인용 근거 |
| 규모 | 전체 건수, 월별 건수, 원문 확보·분류 가능 비율 |
| 모집 | 제출→14일 모집률, 같은 조건 비교군, 차이와 95% CI |
| 계약 | 제출→90일 계약률과 모집→90일 계약률을 별도 제시 |
| 신뢰도 | 표본, 분류 검증, 월별·신규/반복·원문 출처 민감도, 한계 |

우선 후보는 근거가 충분한 것만 제시하며, 개수를 억지로 채우지 않는다. 모집과 계약을 합산해
하나의 점수로 만들지 않고, 인과관계나 마케팅 효과로 표현하지 않는다.

## 재사용할 것과 버릴 것

### 재사용 가능

- `corpus.json`의 비식별 공고 원문, 제출 월·원문 출처
- `outcomes.json`의 모집/계약 성과와 관찰 가능 여부
- `data-manifest.json`, `audit.json`의 입력 해시·원천 대조 기준
- 성과를 숨긴 원문 판독·검증 방식이라는 원칙

### 결론으로 재사용 금지

- 28개 기존 수요 태그와 그 성과 순위
- 기존 후보 1개·조건부 후보 2개
- 이전 분류 코드·AI 라벨·추천 화면

기존 태그는 원문 탐색의 보조 힌트로만 볼 수 있고, 새 타깃의 근거나 비교 단위가 될 수 없다.

## 다음 세션에서의 시작 순서

1. 이 문서를 읽고, 기존 보고서를 ‘폐기된 질문 틀의 탐색 결과’로 취급한다.
2. 전체 원문을 성과 없이 읽을 표본을 잡아 **업종/주체, 업무 문제, 시스템, 사용자·운영 맥락**의
   후보 축을 발견한다. 업종을 추정으로 채우지 않는다.
3. 반복되는 조합마다 포함·제외 기준을 먼저 작성하고, 적은 표본·모호한 조합은 후보에서 제외한다.
4. 기준이 고정된 조합만 전수 분류하고, 원문 대조 표본으로 정확도와 과잉 일반화를 점검한다.
5. 그 뒤에만 모집·계약을 각각 비교하고, 현재 대시보드를 새 결과로 교체한다.

**착수 전에 다시 사용자에게 목표를 물을 필요는 없다.** 위 정의를 기준으로 진행하되, 원문에 업종
근거가 거의 없어 조합 분석이 성립하지 않는 경우에는 그 사실과 가능한 대체 축을 먼저 보고한다.
